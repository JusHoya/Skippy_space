### 2. Serialized prompt queue has no timeout or cancellation: one stalled LLM stream blocks every subsequent prompt to the orchestrator

- **Where:** `apps/agent-runtime/src/skippy.ts:174,185-189; claude.ts:182-201`

## Completeness critic — risk classes the sweep may have missed

# Completeness Critique — risk CLASSES the 10-domain sweep likely missed

The sweep is strong within each named domain, but it audited 10 vertical slices and never traced the seams between them or several whole subsystems. The biggest blind spots cluster around telemetry, the first-run end-to-end path, and the "optional accelerator" memory backends. Prioritized:

### 1. (HIGH) The OTel → collector → Langfuse export path is entirely unaudited — and the documented hook-span contract is unimplemented
None of the 10 domains is "telemetry-export"; `apps/agent-runtime/src/otel.ts` and `packages/otel/src/index.ts` were never read. Two concrete problems are visible:
- `packages/otel/src/index.ts` is still a **Phase-0 stub** (`export function createCollectorConfig` returning `{ _todo: true }`). CLAUDE.md §4 mandates "All agent communication is OTel-traced. PreToolUse/PostToolUse/SessionStart/SessionEnd hooks emit spans." A repo-wide grep finds `PreToolUse|PostToolUse|SessionStart|SessionEnd` **only inside that stub's comment** — the hook adapter does not exist anywhere in `agent-runtime`. So a load-bearing observability contract is theater, exactly the class the persona-identity domain flagged for the psych-monitor but never generalized to telemetry.
- `otel.ts:38-42` soft-fails the entire SDK init, and the OTLP exporter defaults to `http://localhost:4318`. Per MEMORY.md, Docker is still missing, so in the normal dev/desktop launch **every span is silently dropped**, and the BatchSpanProcessor emits continuous connection-refused noise. The sweep's "channel-transport" domain only covered the *envelope→EventBus→Channel* path to the renderer; nobody realized telemetry has **two independent fan-outs** (OTLP vs. envelope channel) and audited the OTLP one.
- **Probe:** read `otel.ts` + `index.ts:50,124`; run the sidecar with no collector and watch for export-error spew and shutdown latency. Verify `@opentelemetry/sdk-node@^0.55` + `@opentelemetry/resources@^1.27` actually accept `new Resource(...)` (the v1→v2 `resourceFromAttributes` migration is called out as a TODO in the file — a version bump could make init throw, hard-disabling telemetry).

### 2. (HIGH) The first-run end-to-end flow is broken by the confirmed key bug AND there is no key-entry UI anywhere
This is the round trip the brief explicitly asked about (launch→prompt→delegate→render), and it was never traced as a unit. `apps/ui/src/hud/Onboarding.tsx:41-83` makes the **very first action a new user takes** a real `dispatchPrompt(SAMPLE_MISSION)` that delegates to the Engineering board. With the confirmed `ANTHROPIC_API_KEY`-not-loaded root cause, the sample mission lands straight in the dead orchestrator — the onboarding is a guaranteed faceplant. Compounding it: a grep for any API-key entry field in `apps/ui/src` returns **nothing** (only `lib.rs`/`sidecar.rs`, the env-forwarding code). So the packaged-build "no production path delivers the key" finding has no UI escape hatch either — the user is never even asked. **Probe:** trace `Onboarding.launchSampleMission → dispatchPrompt → sidecar.rs → skippy.ts` with an unset key and confirm the UI symptom (per the ui-state-pixi findings, it will hang on "thinking…/speaking…" forever with the error buried).

### 3. (MEDIUM) Shutdown under no-collector / no-Letta was never traced — drain can stall the SIGTERM→SIGKILL window
`index.ts:112-125` runs an ordered `drain()` that awaits `shutdownOtel()` **last**. `otel.ts:48` does `await sdk.shutdown()`, which force-flushes the OTLP exporter; against an unreachable `localhost:4318` (the default state) that flush blocks for the exporter's export timeout. The boot-orchestrator domain looked at *startup* and the prompt queue but not the **teardown** path, so nobody checked whether a slow OTel/Letta drain races the Rust shell's kill window in `sidecar.rs`, producing a half-killed sidecar or lost replay tail. **Probe:** read `shutdown.ts` + `sidecar.rs` kill logic; time `drain()` with the collector down.

### 4. (MEDIUM) Letta + embeddings hot-memory round trip — version drift and runtime model download, untraced
The memory-vault domain covered vault jobs (ingest/distill/link/lint) but not the **Letta carryover loop** that Phase 3.5/4 added. `packages/memory/src/letta-client.ts` targets `letta/letta:latest` (floating tag) and hand-rolls fallbacks across drifting REST shapes; the whole "core blocks feed Skippy's context" path degrades to `{ok:false}` **silently** if any of those shapes break — Skippy loses memory carryover with zero user signal. Separately, `packages/memory/src/embeddings.ts` downloads `Xenova/bge-micro-v2` weights from the HF Hub **on first use** — an un-flagged outbound network call from a "local" sidecar that silently returns `null` (no semantic retrieval) in a packaged/offline build. **Probe:** trace `letta-bootstrap.ts` → `skippy.ts` context assembly; force a Letta 404 and confirm the degradation is observable; check whether the installer ships cached embedder weights.

### 5. (MEDIUM) Replay crash-recovery contract is half-audited (writer ↔ reader ↔ scrubber)
The boot-orchestrator domain noted prompt loss on child crash, but the **replay** subsystem (`replay-writer.ts` writer ↔ `apps/shell/src-tauri/src/replay.rs` reader ↔ renderer `ReplayScrubber`) was never traced end to end. A sidecar crash mid-`appendToReplay` leaves a **partial/truncated final JSONL line**; `replay.rs::replay_load` returns raw contents and the renderer parses them — nobody verified the parser tolerates a torn tail rather than throwing and bricking replay of the very session that crashed (the one you most want to inspect). **Probe:** read `replay-writer.ts` flush semantics + the renderer's `.jsonl` line parser; simulate a truncated last line.

### 6. (MEDIUM) git-only vault versioning fails silently — the only durable backup
`git_autocommit.rs` is the sole implementation of PRD §8.2 "git-only vault sync," yet every failure path (`git status/add/commit` non-zero) just `bus.publish(warn)` and returns `Ok(false)` (lines 115-122, 136-144, 165-172). A persistently locked/corrupted `.git/index`, a detached HEAD, a pre-commit hook that **prompts** (the tokio `Command` has no stdin and would hang the 5-min loop), or a signing prompt all **silently stop all vault versioning forever** with only a transient log line. This is a data-durability class the sweep didn't touch (it's neither memory-vault's job logic nor channel-transport). **Probe:** read the whole file (done) and test against a repo with a blocking `pre-commit` hook and a lock held.

### 7. (LOW-MEDIUM) Cross-domain envelope-contract parity was never verified as a whole
Each domain validated its own envelopes; nobody diffed **producer vs. consumer** coverage across the wire. Confirmed asymmetry: `delegation_complete` IS handled in `apps/ui/src/lib/channel.ts` but (per the delegation finding) is **never fed back to Skippy** — so the renderer and the orchestrator disagree about mission outcome. There is likely more of this (e.g., `replay_session`, `set_model` in-flight semantics, `truncated`). **Probe:** enumerate every `type:` literal emitted by `writeEnvelope` across `agent-runtime/src/*` and cross-check against the renderer's `channel.ts` switch and the Rust `envelope.rs` enum for orphans on either side.

### 8. (LOW) n8n is specified but provisioned nowhere
`docs/PRD.md` / `docs/architecture.md` name n8n as part of the stack (DevOps board automation), but there is **no `infra/n8n/`**, no compose service, and zero source references (the grep hits were only Rust build artifacts under `target/`). Whether this is intentional deferral or a dropped requirement is an unverified contract — it should be an explicit `OQ-`/PRD note, not a silent gap. **Probe:** grep PRD for the n8n requirement section and reconcile against `infra/docker-compose.yml` (only langfuse/otel-collector/letta are `include`d).

### 9. (LOW) Windows path/encoding class only partially covered
The pty-claudecode domain nailed Windows spawn, but the broader Windows-specific surface — vault file writes (CRLF/UTF-8-BOM round-tripping in atomic.ts), case-insensitive filename collisions and reserved device names (`con`, `aux`) in ULID-derived note paths, `>260`-char path limits, and replay filenames — was not traced. On an app whose entire premise is a local Windows 11 vault, these are realistic. **Probe:** read `packages/memory/src/atomic.ts` + `frontmatter.ts` write paths and the ULID→filename mapping; check for path-length and reserved-name guards.

**Net:** the two gaps most likely to bite a real user on day one are #2 (the onboarding sample mission detonates on the confirmed key bug, with no UI to supply a key) and #1 (the mandated OTel/hook tracing is a stub, so when things break the operator is blind). #3, #4, and #6 are the silent-degradation tail that will erode trust over longer sessions.
